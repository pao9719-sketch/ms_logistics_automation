# PRD: AI 기반 납품물량 자동 인식·검증 시스템

| 항목 | 내용 |
|---|---|
| 문서 상태 | Draft v0.1 (기획서 `ms_logistics_automation.md` 기반, 2026-10-13) |
| 대상 조직 | MS가스 구매물류 |
| 범위 | MVP(1차). ERP 직접 연동 등 2차 범위는 §9 |
| 구현 현황 표기 | ✅ 구현됨 · 🟡 부분/가정 있음 · ⬜ 미구현 |

## 1. 배경과 문제

납품물량 업무는 운행일지·계근표를 사람이 확인해 엑셀에 입력하고, 거래처·사업장별로 분류·대조한 뒤 ERP에 입력하고 월말에 정산한다. 반복 입력과 대조에 시간이 들고, 누락·수량 불일치는 원본을 다시 찾아 수정해야 하며, 오류가 월말에 몰린다.

## 2. 목표와 비목표

**목표**
1. 운행일지·계근표의 주요 항목을 자동 인식한다.
2. 문서 간 납품물량을 자동 대조해 불일치·누락·중복을 일 단위로 탐지한다.
3. 검증·승인된 데이터만 ERP 입력용 엑셀로 출력한다.
4. 모든 수정·승인 이력과 원본 증빙의 추적성을 확보한다.

**비목표(MVP)**: ERP 직접 연동, 대시보드·통계, 로그인/권한 체계, 기존 외주 시스템 대체.

## 3. 사용자

| 역할 | 하는 일 | 핵심 니즈 |
|---|---|---|
| 구매물류 담당자 | 자료 업로드, 인식 결과 검수·수정, 오류 처리 | 입력 시간 절감, 오류를 놓치지 않기 |
| 구매물류 책임자 | 미처리 건·월말 자료 확인 | 마감 전 미검증 건 가시성 |

## 4. 핵심 원칙 (제품 제약)

- **P1** 증빙이 부족하거나 수량이 맞지 않으면 AI가 임의로 정상 처리하지 않는다. 담당자 확인 전까지 미검증 상태를 유지한다.
- **P2** 읽을 수 없는 값은 추정하지 않고 비운 뒤 검수 대상으로 분류한다.
- **P3** AI 원본값과 수정값을 구분 저장하고 수정자·시각을 남긴다.
- **P4** 기존 업무 흐름과 엑셀 양식을 유지한다. ERP 연동은 후순위.

### 오류 유형 정의

| 유형 | 판정 | 후속 조치 |
|---|---|---|
| 매칭실패 | 거래처/품목이 기준정보에 없음, 문서 간 단위 불일치 | 기준정보·별칭 보완 또는 값 수정 |
| 수량불일치 | 운행일지 합계 ≠ 계근표 합계(허용오차 초과) | 원본 확인 후 수정 또는 사유 기록 |
| 자료누락 | 한쪽 문서만 존재 (반대편에 다른 거래처/품목 기록이 있으면 힌트 표시) | 자료 추가 확보 |
| 중복의심 | 같은 문서종류에 일자·차량·거래처·품목·수량이 동일한 기록 복수 | 복수 운행이면 사유와 함께 처리 |
| 인식불확실 | 필수값 누락, 신뢰도 임계 미만, 불확실 필드, 총중량−공차≠순중량 | 원본 확인 후 수정·승인 |

## 6. 업무 흐름

`업로드 → 인식/파싱 → 기준정보 매칭 → 자동 대조·오류 탐지 → 담당자 검수(수정·승인) → 오류 처리 → 엑셀 출력`

ERP 입력 대상 = 운행일지·계근표가 모두 있고, 구성 기록이 전부 검수 완료이며, 열린 오류가 없는 납품 건(수량은 계근표 합계). 그 외는 '오류·미검증' 시트로 분리한다.

## 8. 열린 질문 (개발 전 확정 필요)

1. 운행일지와 계근표의 대응은 1:1인가, 복수 운행이 한 계근표에 묶이는가? → F4 그룹 규칙 확정
2. 계근표의 어떤 값이 납품수량인가(순중량?), 단위 환산 기준(품목별 kg↔톤 등)은?
3. ERP 입력 양식(컬럼·순서·코드 체계)은?
4. 허용 오차를 둘 것인가(계근 오차 범위)?
5. 문서 양식은 몇 종류이며 샘플(정상·오류)은 어디서 받는가?
6. 외부 AI 서비스로 문서 이미지를 전송해도 되는가? 불가 시 사내 OCR 대안은?
7. 기존 대시보드/외주 시스템과 기능이 중복되는가?
8. 원본 이미지·추출 데이터 보관 기간은?

## 9. 단계와 범위

| 단계 | 내용 | 산출물 |
|---|---|---|
| M0 (완료) | MVP 구현 | 본 저장소 |
| M1 | 실제 문서 샘플로 인식 정확도·규칙 보정, ERP 양식 확정 | 테스트 결과서, 규칙 개정 |

# MS가스 납품물량 자동 인식·검증 시스템 (MVP)

`ms_logistics_automation.md` 기획서의 1차 구축 범위 구현.
**업로드 → AI 인식 → 기준정보 매칭 → 운행일지↔계근표 대조 → 오류 탐지 → 담당자 검수 → 엑셀 출력**

## 실행

```powershell
pip install -r requirements.txt
python scripts/make_samples.py          # 선택: 오류가 섞인 데모 데이터 → sample_data/
python run.py                           # http://127.0.0.1:5000
python -m pytest                        # 테스트
```

데모 순서: 기준정보 → `customers.xlsx`, `items.xlsx` 업로드 → 납품자료 → `운행일지_샘플.xlsx`(운행일지),
`계근표_샘플.xlsx`(계근표) 업로드 → 오류 검증 화면 확인.

## 환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `ANTHROPIC_API_KEY` | - | 설정하면 이미지/PDF를 Claude 비전으로 인식. 없으면 '인식대기'로 등록(수동 입력·엑셀 업로드 사용) |
| `MSLOG_OCR_PROVIDER` | key 유무로 자동 | `claude` / `none` |
| `MSLOG_OCR_MODEL` | `claude-sonnet-5-5` | 인식 모델 |
| `MSLOG_CONFIDENCE_THRESHOLD` | `0.85` | 미만이면 '인식 불확실' |
| `MSLOG_QTY_TOLERANCE_RATIO` | `0` | 수량 허용 오차 비율(0=완전 일치) |
| `MSLOG_DATA_DIR` | `./data` | DB(SQLite)·원본 파일 저장 위치 |
| `MSLOG_HOST` / `MSLOG_PORT` | `127.0.0.1` / `5000` | 접속 허용 범위 |

## 기획서 대응

| 기획서 | 구현 |
|---|---|
| 파일 업로드·중복 확인 | `service.py` — 내용 해시로 동일 파일 중복 등록 차단, 원본 보관 |
| AI 문서 인식 | `ocr.py` — 확인 불가 값은 null + 불확실 필드로 반환(추정 금지). 엑셀은 `excel_in.py` |
| 거래처 매칭 | `masters.py` — 코드·명칭·별칭 **정확 일치만 자동 매칭**, 유사 명칭은 후보로만 표시 |
| 물량 대조·오류 탐지 | `verify.py` — 일자·차량·거래처·품목 기준 그룹 대조. 매칭실패·수량불일치·자료누락·중복의심·인식불확실 |
| 담당자 검수·이력 | `review.py` — 수정 전후값·담당자 기록, AI 원본값(`ai_json`) 별도 보존 |
| 엑셀 출력 | `export.py` — ERP입력, 일자별, 차량별, 거래처·사업장별, 월말누적, 오류·미검증 시트 |

### 핵심 원칙(코드로 강제)
- 규칙을 통과하지 못한 건은 **열린 오류로 남고**, 담당자가 수정하거나 사유를 적어 처리하기 전까지 승인할 수 없다.
- 검수 완료된 기록을 수정하면 **미검수로 되돌아가** 재승인이 필요하다.
- ERP 입력 시트에는 운행일지·계근표가 모두 있고 전부 검수 완료·오류 없는 건만 들어간다(수량은 계근표 합계). 나머지는 '오류·미검증' 시트로 분리된다.
- 원본이 없거나 읽을 수 없는 값은 비워 두며 임의로 채우지 않는다. 연도가 없는 날짜는 해석하지 않는다.

## 확정이 필요한 가정 (기획서 §3 '확인 필요' 사항)

1. **대조 단위**: (납품일자, 차량번호, 거래처, 품목)별로 운행일지 수량 합계 ↔ 계근표 수량 합계를 비교한다. 1:N 대응 규칙이 다르면 `verify.build_groups`를 조정한다.
2. **계근표 수량**: 순중량을 `수량`으로 사용. 무게 단위(kg/톤/t)는 kg로 환산해 비교, 그 외 단위는 동일 단위끼리만 비교한다.
3. **ERP 입력 양식**: 양식 샘플이 없어 `config.ERP_COLUMNS`에 임시 컬럼을 두었다. 실제 양식을 받으면 이 목록만 수정한다.
4. **중복 의심**: 같은 문서종류에서 일자·차량·거래처·품목·수량이 모두 같으면 표시한다. 정상적인 복수 운행이면 사유와 함께 '처리'한다.

## 한계 / 후속 과제

- Claude 비전 인식(`ocr.py`)은 실제 API 호출 경로로 **자동 테스트되지 않았다**. 실제 운행일지·계근표 이미지로 정확도 측정(기획서 §7 시범 운영)이 필요하다.
- 로그인/권한이 없다. 담당자명은 화면 상단 입력값(쿠키)이며 사내망 공유 전 접근통제를 붙여야 한다(기획서 §9.1). 기본 바인딩은 `127.0.0.1`.
- 이미지/PDF는 외부 AI 서비스로 전송된다. 사내 보안정책 확인 전에는 `MSLOG_OCR_PROVIDER=none`으로 운영한다.
- `.xls`(구형 엑셀)는 미지원 — `.xlsx`로 저장해 사용.
- 2차 범위(ERP 직접 연동, 대시보드, 통계)는 미구현.
